# Plan Delivery

Owner: **Delivery Manager**

## Inputs

Use primarily:

- approved `opportunity-brief.md`;
- approved `solution.md`, including tasks, qualitative complexity, dependencies and profile types.

Reopen original evidence only when a specific delivery constraint cannot be resolved from approved artifacts.

## Responsibilities

Define an appropriately bounded delivery plan:

- recommended methodology/lifecycle: agile, waterfall, hybrid or custom;
- rationale for that choice;
- inception/discovery/landing step when appropriate;
- workstreams/lines of work;
- sequencing and dependencies;
- meaningful milestones and decision gates;
- acceptance/integrated validation;
- release/cutover/transition/handover;
- customer and third-party participation;
- project governance model;
- governance roles and forums/ceremonies;
- delivery risks and TBDs.

The plan must reflect the implementation tasks and dependencies in `solution.md`.

## Estimation boundary

Do NOT invent:

- person-days/hours;
- story points;
- team size/FTE counts;
- numeric project duration;
- cost/price/margin.

Qualitative task complexity belongs in `solution.md`; the Delivery Manager may use it for sequencing and risk reasoning but must not convert it to numbers.

## Canonical output

`delivery-plan.md`
